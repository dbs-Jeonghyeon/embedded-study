## 한 일
- 레퍼런스 매뉴얼(RM0390)에서 RCC와 GPIO 레지스터 부분을 훑어봄
- 레지스터를 직접 제어해 PA5(보드 LED)를 깜빡이는 코드를 작성하고 빌드 성공을 확인함
- HAL 버전과 같은 동작을 어떤 레지스터 조작으로 하는지 대응시켜 봄

## 개념 정리
- 레지스터 : 주변장치(GPIO, 타이머 등)를 제어하는 특수한 메모리 칸. 주소가 정해져 있고 값을 쓰면 하드웨어가 동작함 -> volatile 포인터로 접근
- HAL vs 레지스터 직접 제어 : HAL은 레지스터 조작을 함수로 감싼 것. 베어메탈은 매뉴얼을 보고 레지스터를 직접 만짐
- 클럭 활성화 : STM32는 기본적으로 주변장치 클럭이 꺼져 있어서 켜지 않으면 GPIO 레지스터에 써도 동작하지 않음. RCC의 AHB1ENR 0번 비트(GPIOAEN)를 1로 쓰면 GPIOA 클럭이 켜짐
- MODER : 핀 모드 설정 레지스터. 핀당 2비트(00 입력 / 01 출력 / 10 대체 기능 / 11 아날로그). PA5는 11:10번 비트를 01로 설정
    - 설정할 때 먼저 &= ~(3 << 10)으로 지운 뒤 |= (1 << 10)으로 씀
- ODR vs BSRR : ODR은 출력 값 자체를 쓰는 레지스터라 토글하려면 읽고 반전해서 다시 써야 함. BSRR은 하위 16비트에 1을 쓰면 해당 핀이 High, 상위 16비트에 1을 쓰면 Low가 되고, 0을 써도 다른 핀에 영향이 없음 -> 읽고 쓰는 과정 없이 한 번에 처리됨
- 딜레이 : for 루프로 시간을 끄는 busy-wait. 루프 변수에 volatile이 없으면 컴파일러가 루프를 지울 수 있음
- HAL ↔ 레지스터 대응
    - __HAL_RCC_GPIOA_CLK_ENABLE() ↔ RCC_AHB1ENR |= (1 << 0)  (GPIOA 클럭 켜기)
    - HAL_GPIO_Init() ↔ GPIOA_MODER 설정 (PA5 출력 모드). HAL은 구조체로 출력 타입(푸시풀), 풀업/풀다운(NOPULL), 속도(LOW)도 함께 설정하는데, 레지스터 버전은 MODER만 건드리고 나머지는 리셋 기본값을 그대로 씀
    - HAL_GPIO_TogglePin() ↔ 켜기/끄기를 BSRR로 따로 씀 (HAL은 토글 한 줄, 레지스터 버전은 켜기·끄기 두 줄). 레지스터로 토글 한 줄로 하려면 GPIOA_ODR ^= (1 << 5)
    - HAL_Delay(500) ↔ for 루프 딜레이. HAL_Delay는 SysTick이 1ms마다 올리는 카운터를 기준으로 500ms를 기다리고, for 루프는 반복 횟수만 정해서 실제 시간은 클럭·최적화에 따라 달라짐
