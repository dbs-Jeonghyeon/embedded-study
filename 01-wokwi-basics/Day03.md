## 개념 정리
- volatile : 컴파일러가 변수를 매번 메모리에서 읽도록 하는 키워드. 설정하지 않으면 컴파일러가 최적화로 값을 한 번만 읽어 레지스터에 복사해 두고 재사용할 수 있음 -> 인터럽트가 메모리의 값을 바꿔도 반영 X / 쓰는 경우 : 인터럽트와 공유하는 변수, 하드웨어 레지스터, 다른 태스크와 공유하는 플래그
- 메모리 영역 : 코드(.text)는 Flash(비휘발성), 데이터(.data/.bss)·힙·스택은 SRAM(휘발성)
    - .data : 초기값이 있는 전역 변수. 초기값은 Flash에 저장되어 있다가 부팅할 때 SRAM으로 복사됨
    - .bss : 초기값이 없는 전역 변수. 부팅할 때 0으로 채워짐
    - 힙 : malloc으로 할당하는 영역, 낮은 주소에서 높은 주소로 자람
    - 스택 : 지역 변수와 함수 호출 정보, 높은 주소에서 낮은 주소로 자람. 마지막에 쌓인 것이 먼저 나감(LIFO)
- Flash와 SRAM : Flash는 전원을 꺼도 유지되지만 실행 중 쓰기가 어렵고 SRAM보다 느림 / SRAM은 빠르고 자유롭게 쓸 수 있지만 전원을 끄면 사라짐
- PROGMEM : AVR은 Flash와 SRAM의 주소 공간이 분리되어 있어 const만 쓰면 SRAM에 복사됨. PROGMEM을 쓰면 Flash에 두어 SRAM을 아낌 / 단점 : 읽을 때 pgm_read 계열 함수가 필요하고 코드가 번거로워짐 -> SRAM 사용량을 측정한 뒤 필요한 곳에만 사용
- malloc : 실행 중에 힙에서 메모리를 할당받는 함수. 연속된 빈 공간이 요청 크기보다 작으면 NULL을 반환하므로 반환값 확인이 필수이고, 다 쓰면 free로 반납해야 함
    - 임베디드에서 피하는 이유 : 힙이 작음, 조각화로 총량이 충분해도 실패할 수 있음, 실패를 실행 중에야 알게 됨, 할당 시간이 일정하지 않음, 힙과 스택이 겹쳐도 경고가 없음
    -> 크기를 미리 정한 전역 배열이나 static을 사용
- 시리얼 통신 : 데이터 선 1줄로 1비트씩 순서대로 보내는 방식. 클럭 선이 없는 비동기식(UART)의 경우, 송수신 양쪽의 보율을 맞춰야 함.

## 실습
문제 발생 : volatile 없이 while (!pressed) { } 로 버튼을 기다리는 코드에서 버튼을 눌러도 "pressed!"가 출력되지 않고 멈춤
원인 : 컴파일러가 루프 안에서 pressed가 바뀌지 않는다고 보고 처음 읽은 값(false)만 계속 확인함. 인터럽트가 메모리의 값을 true로 바꿔도 루프는 이를 보지 못함
해결 : pressed 선언에 volatile 추가 -> 버튼을 누르면 "pressed!"가 출력됨
배운 점 : 인터럽트와 메인 코드가 함께 쓰는 변수에는 volatile이 필요함. volatile이 없어도 delay 같은 함수 호출 때문에 우연히 동작할 수 있어서, 동작 여부와 상관없이 붙여야 함
