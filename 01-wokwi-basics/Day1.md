## 개념 정리
- INPUT_PULLUP : 버튼을 안 누르면 HIGH 상태로, 누르면 GND와 연결되어 LOW가 됨
    내부 풀업 저항을 켜, 핀을 약하게 HIGH 쪽으로 고정함
    풀업이 없으면 누르지 않을 때 핀이 플로팅 상태가 되어 잡음 때문에 값이 불안정해짐
- 폴링 : 루프에서 계속 반복해서 상태를 확인하는 방식
    장점: 코드가 단순함
    단점: delay 같은 다른 작업 중에는 확인하지 못해 입력을 놓침, delay를 빼면 놓치지는 않지만 CPU가 계속 확인하느라 바쁨
- 인터럽트 : 이벤트가 발생하면 하던 일을 멈추고 ISR(인터럽트 서비스 루틴)을 실행한 뒤 돌아오는 방식
    delay 중에서도 즉시 반응함
    주의 : ISR은 짧게 작성하고, 안에서 delay 금지, 변수 선언 시 volatile 사용
- volatile : 컴파일러로 하여금 변수를 매번 메모리에서 읽도록 설정하는 키워드
    설정하지 않으면, 컴파일러는 최적화를 위해 변수를 최초에 한 번만 읽고 재사용할 수 있음 -> 이후의 변화는 반영 X
- 채터링 : 버튼을 누르거나 뗄 때 접점이 튕겨서 신호가 짧은 시간 동안 여러 번 바뀌는 현상
- 디바운싱 : 채터링으로 인한 부작용을 처리하는 기법

## 실습
- 문제 발생 : Serial.println(count)의 결과가 버튼을 누를 때마다 1씩 증가할 거라는 예상과는 다르게 160 전후로 증가함
- 원인 : 버튼을 누를 때 접점이 튕겨서 채터링이 발생해 예상치를 웃도는 결과가 발생함
- 해결 1 : lastPress로부터 특정 시각 내의 신호를 무시함
    -> count가 누를 때 한 번, 뗄 때 한 번 증가하여 총 2가 증가함
- 해결 2 : digitalRead 값이 Low일 때만 count를 증가시켜, 뗄 때의 변화는 세지 않음
    -> 의도대로 누른 것만 카운트됨
- 배운 점 : 버튼 입력은 채터링 때문에 한 번의 입력이 여러 번으로 인식될 수 있음
    디바운싱에서는 "버튼을 누르고 언제부터 측정하는가"가 결과를 바꿈
